# Pacer MVP Implementation Plan

> **For Hermes:** Execute this plan as vertical slices with strict file ownership and TDD.

**Goal:** Deliver a secure, mobile-first healthy-habit competition MVP with auditable peer review and ledger-derived ranking.

**Architecture:** React feature modules call explicit query/mutation boundaries backed by Supabase. PostgreSQL RLS is the default authorization layer; security-definer RPCs own review and score mutations. Semantic design tokens provide controlled group theming.

**Tech Stack:** React, strict TypeScript, Vite, React Router, TanStack Query, Tailwind, Radix, CVA, Storybook, Supabase, Zod, React Hook Form, Vitest/RTL, Playwright, PWA.

## Phase 1 — Foundation

1. Verify Node/npm/git/Supabase/Graphify versions and repository state.
2. Scaffold strict Vite application and quality scripts.
3. Write product, architecture, domain, permissions, design, and testing docs.
4. Add initial schema, constraints, RLS, trusted RPC boundaries, and local Supabase config.
5. Add semantic token contract, primitives, stories, and responsive application shell.
6. Add CI, test harnesses, environment validation, PWA metadata, and Graphify map.
7. Pass format, lint, typecheck, unit, build, and Storybook build.

**Acceptance:** clean checkout installs with `npm ci`; no committed secret; graph and workflow documented; shell works at iPhone/Android widths.

## Phase 2 — Secure vertical slice

1. Auth and profile onboarding.
2. Group create + invite/join.
3. Challenge + habit configuration.
4. Evidence upload through a private bucket and validated adapter.
5. Submission creation and review queue.
6. Authorized second-user review RPC writes review, status event, audit event, notification, and immutable ledger entry atomically.
7. Ranking query derives totals from ledger.
8. Add RLS regression tests and two-user Playwright flow.

**Acceptance:** self-review, removed-member evidence access, and direct point forgery fail; valid review updates ranking.

## Phase 3 — Product completion

Period rankings in group timezone; activity histories; heatmap; current/best streaks; notifications; settings; members; constrained theme personalization; profile photo selection from the device gallery with validated per-user Storage upload; global personal habit creation propagated to draft challenges in every administered group without mutating published rules; complete reusable components and stories.

## Phase 4 — Hardening

Accessibility and reduced-motion audit; offline/loading/error states; optimistic update reconciliation; upload limits; DST/month boundaries; RLS regression suite; critical E2E on mobile profiles; performance budgets; fresh Graphify map; clean-checkout documentation rehearsal.

Agents must report decisions, changed files, tests run, and unresolved risks. The lead reviews diffs and runs repository-wide gates; agent claims are not accepted as verification.

## Risks

- **RLS recursion/privilege escalation:** small `SECURITY DEFINER` helpers, fixed search path, revoke public execute, SQL policy tests.
- **Timezone/DST errors:** IANA zones and database-side period fixtures around DST/year boundaries.
- **Ledger drift:** append-only triggers and one atomic review/reversal transaction.
- **Private evidence leakage:** private bucket plus storage-object policies tied to active membership.
- **Realtime races:** invalidate authoritative queries after events; optimistic state is never score truth.
- **PWA cache staleness:** conservative app-shell caching; never cache private evidence responses.
